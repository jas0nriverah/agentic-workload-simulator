## Serving observer: minimum defensible integration

**Deferred posthoc attribution is valid for late-arriving evidence; it does not repair an inadequate measurement window.** The synchronous `_read_witness()` should remain fail-closed. Raw snapshots already survive a missing witness. A later sidecar can add an attribution supported by new immutable evidence without rewriting the original terminal status or using it as a prospective feature.

Integration choices for main’s decision (the subsequent ASGI feasibility update below conditionally favors the pinned middleware path):

1. **Use existing server-side logs only if they actually satisfy completeness and identity.** Ordinary Uvicorn/vLLM text access lines, a launcher log path, and point samples of running/waiting gauges are not enough by themselves. They may omit physical IDs, arrival times, unfinished/error requests or bypass traffic. Inventory what the real observer sees before describing it as independent. A client that emits the only access log is not independent of the client being audited.
2. **Prefer a small server-host gateway/observer if a complete existing source is unavailable.** It must observe every ingress route to the serving process, preserve the forwarded physical request ID, server process/start identity and counter epoch, classify model versus observer/metrics traffic, and journal request start/terminal/cancel/disconnect with ordered durable sequence numbers. Enforce or demonstrate that direct/backend access cannot bypass it. A detached client/sidecar with access to only its own requests is insufficient. This can avoid restarting all 22 vLLM servers if routing/access control makes the existing backend non-bypassable; that feasibility is unverified here. It is an implementation recommendation, not approval to deploy or restart.
3. **Establish engine quiescence as well as HTTP ownership.** Start observation before the before-snapshot. Account for requests already in flight, retries, cancellation and work persisting after disconnect; do not release/reassign the endpoint while old inference may continue. Native inflight/queue state and completion/cancellation evidence supplement the complete request stream. Gauges equal to zero at two instants cannot alone exclude a request between those instants. An ordinary HTTP access logger may end a request before engine-side metric publication, so its terminal time alone is not a counter-flush witness.
4. **Bind the exact clock/window.** Best minimal design: the server-host observer also records the before/after metrics requests and their actual fetch start/end bounds in its own proven clock domain, linked by unique scrape IDs and raw hashes to the proxy snapshots. Otherwise retain paired clock samples with explicit host/boot/domain and uncertainty; reject attribution if the conservative expanded window admits other model traffic. Root has now added actual `scrape_started_monotonic_ns`/`scrape_ended_monotonic_ns`, same hostname/boot/clock checks and overlap rejection; this reviewer inspected those changes. Root reports 40 serving-module tests passed, not rerun here. This closes the identified local scrape-bracketing gap, but local proxy bounds still cannot be compared directly with remote server monotonic timestamps. The current strict access-log schema needs an explicit reviewed companion/schema binding for this evidence; its numeric window fields do not establish a common clock. Also validate the witness's window against the actual two scrapes, not merely request/server/epoch strings.
5. **Finish attribution after a completeness watermark, without blocking the measured request for log arrival.** Persist loss/gap/rotation/restart status and a watermark proving observation through the window end, including pending requests. Derive a hash-bound sidecar referencing raw before/after snapshots, scrape window, independent access segment, lease and epochs. Preserve request-wall versus server-component semantics. Run the existing exact histogram count-delta-one and finite/nonnegative/reset checks for each claimed metric; different families may become visible at different times. Native server metrics still are not automatically GPU kernel time.

**Counter-update race:** if the immediate after-snapshot predates publication, a later access log does not change its count delta. The component must remain unavailable for that pair. A later raw scrape can support a new derived pair only if the observer proves a sufficiently wide uncontaminated interval, the previous request's updates were settled before the original baseline, and the relevant family has exactly one attributable update. Asynchronous bounded snapshots can retain such opportunities without waiting in the agent loop, but next-request overlap can legitimately prevent per-request attribution. Do not hold the next request solely to force a favorable delta, allocate an aggregate among requests, or call count-delta-one sufficient when a previous request's delayed update could supply that one count. If mandatory native components cannot be attributed, main must resolve capture or accept an explicit claim limitation before freeze; raw snapshots alone cannot guarantee future recovery.

**Updated ASGI recommendation — feasible, conditional, not restart authorization.** Root reports inspection of the actual pinned remote vLLM `api_server.py`: class ASGI middleware is supported through `--middleware`. This capability finding is root-reported; this audit did not independently access the remote source. Given that path, a server middleware observer is a defensible minimal integration candidate, rather than necessarily a last resort. It can independently observe actual server ingress and capture request and metrics windows in one server clock domain, avoiding the need to make the proxy’s immediate witness read succeed. Main owns adoption. No restart has been decided or performed by this reviewer.

For a proposed implementation, main should require:

- Wrap ASGI receive/send transparently: record the exact forwarded physical ID and server-generated observation ID, method/route, request arrival, body completion/hash, response start, final body/stream completion, disconnect/error and pending state. Preserve body bytes or a bound raw server archive where required; do not consume a body twice, alter chunks, buffer an entire stream merely to log it, or derive physical IDs from a success-only client log. Observe all inference routes and classify metrics/health traffic separately. Bind server process/start, observer source hash, lease and counter epoch.
- Retain server-side raw metric snapshots with complete fetch/sample brackets, hash and scrape ID in the observer’s own hostname/boot/clock domain. Capture before ingress dispatch and after completion where feasible without blocking the ASGI event loop or recursively intercepting the observer’s own metrics fetch. A single server clock avoids cross-host timestamp arithmetic for native attribution; proxy/server records join by exact physical ID and hashes. Any cross-host timeline display still needs proven clock alignment and uncertainty. Neither matching numeric nanoseconds nor matching wall-clock formatting establishes alignment.
- Persist append-only start/terminal records and a completeness watermark; preserve inflight/error/disconnect observations on interruption. Derive attribution later from the server-owned snapshots/access stream. Keep proxy-native unavailable records immutable and produce new hash-bound sidecars. Middleware response completion is not necessarily engine cancellation completion or metric publication; retain the counter-update and inflight safeguards above. Do not wait in the measured trajectory solely for a witness or counter to become available.
- Prove the integration on **one controlled vLLM restart only after main authorizes it**. Preserve the pinned model/tokenizer, weights, effective serving/cache flags and relays; add only the reviewed observer loading configuration. Record before/after launch argv, process/epoch identities, observer loading and source hashes, endpoint/relay continuity, exact request/response preservation, and collector overhead. Exercise successful and streaming requests, foreign traffic, failed/partial/disconnected requests, delayed counter/log publication and observer failure. Passing API health alone is insufficient.
- Roll out to the remaining requested endpoints only after that gate passes and main adopts the result. Preserve one-trajectory-per-endpoint leases and the shared-CPU contention disclosure. Do not infer that one middleware instance sees bypass ingress or other serving processes: verify the actual server topology, routes and ingress ownership, including any multiple API workers.

The controlled restart proof is a bounded integration gate for the existing serving stack, not a new model or optional hardware-validation campaign. It does not waive the existing full-capture overhead requirement. A client-only lease remains rejected even if supplied to this middleware.

## What the 55.98% finding does and does not establish

The historical report states that recorded CPU+GPU sums leave **55.98% of eligible E2E mass unassigned**, and for **716/860** trajectories `1.25 × observed_event_sum < 0.75 × observed_E2E`. This is a saved aggregate, not newly inspected labels. It is distinct from the selected historical case's 51.644029% residual and is not a claim about current production capture.

For the same nonoverlapping additive event definition, every event prediction passing the upper 25% bound implies predicted sum <=1.25×observed sum. Where that is below 0.75×E2E, an event-sum-only E2E prediction cannot pass simultaneously. The corrective implication is complete boundary/event accounting, not an arbitrary multiplier. If actual events overlap, use a declared dependency/interval composition; blindly summing nested syscall/tool/request/server events is also invalid.

The percentage alone cannot identify startup versus retries versus client work, cannot prove 55.98% was CPU execution, and cannot tell how much shared-host contention contributed. Existing named phases, raw physical requests and clock-safe complements are sound improvements, but their joint live coverage is still unproven. File/script work descriptors address within-tool prediction error; they do not explain missing outer time. More budget, a new prompt, pager changes or an exact-command lookup cannot be claimed to close this accounting gap without matching measured evidence. Retain UNKNOWN and unsupported events; neither relabel them nor omit them to pass universal accuracy.
