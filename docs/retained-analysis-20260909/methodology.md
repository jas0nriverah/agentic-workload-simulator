Neither is evidence of equivalence or a current optimum. Small output caps, temperatures above zero and reduced calls show losses and supply no reason to expand the candidate set. ## D9 priorities and target separation

1. **Compose the retained physical requests and lifecycle intervals correctly.** The old CPU+GPU-only formulation is arithmetically incapable of meeting both gates in 716/860 eligible historical trajectories. That is a boundary result, not evidence that the accepted collector still lacks data. Current [reconstruction](../measurement-review-20260909/reconstruction.md) proves a clock-safe outer interval union and explicit unknown complement. New predictions must estimate lifecycle/unknown contribution from training information; the evaluated run's observed complement is a label and cannot be inserted into its prediction. Nested intervals and duplicate request representations cannot be summed as separate work.
2. **Prioritize work heterogeneity within shell, test and traversal.** Those original classes contain 4368/5520 CPU misses and 93.3% of absolute-error mass in the eligible historical diagnostic. Finer observed-work descriptors, valid script prestate and actual executable/scope offer an explanation to investigate within the existing semantic formulation. Exact-command medians, guessed visited-file counts or changing scalar centers cannot establish a physical cost law. The historical semantic-median fit predates the broader exclusion and is not newly clean out-of-sample evidence.
3. **Inspect fixed versus token-dependent request cost.** Short-output requests contribute 943/1145 historical request misses but also most requests. Native service, queue, client and transport phases can distinguish candidate explanations; short outputs alone do not establish transport as the cause. Preserve observed versus predicted target boundaries. Native service wall is not CUDA occupancy, and syscall returned bytes are not physical disk bytes.

The [assignment formulation](../D9_ASSIGNMENT_FORMULATION.md) permits explicitly disclosed conditional replay using realized tokens/work. Prospective prediction instead needs only information available before the event: neither future script state nor current-event failure/latency can choose its features. Current-event durations, official outcomes and target-specific fitted hardware parameters are excluded from both protocols. Hardware transfer remains an unvalidated assumption where only one reference platform supplies evidence; CPU thread count and GPU count do not justify universal linear speedups.

Historical CPU accuracy measures tool-event durations. The current accepted reconstruction also retains individual syscall operations: 846533 operations across 100 action boundaries in its fixture. These are different target populations and boundaries. Historical tool pass rates cannot certify atomic-operation accuracy or be compared numerically to a new syscall pass rate as if only the estimator changed. The richer mapping supports the explanations that older D8 examples lacked; it does not require replacing those examples or selecting a new one.

The current fixture also distinguishes 40 semantic tool calls from 60 auxiliary runtime commands. Its semantic tool rows total 18491.611631 ms; the larger 32634.391398 ms host `tool_execution` interval union includes both populations. That union is not a semantic-only class sum. Preserve both definitions in CPU/GPU ratios and composition rather than treating a plotting-label ambiguity as absent acquisition.

For any later authorized model comparison, first keep all repeated instances together and use only the declared training partition. Freeze the descriptor contract, comparison and coefficients before final evaluation. Report within-25% coverage on every original event class, required-event completeness, tails, CPU sums, direct E2E, lifecycle-aware E2E, and the conjunction of **every required individual event AND E2E within 25%**. Mean error, p95 and a large passing fraction cannot establish the literal universal requirement. Missing, unsupported and censored required events remain visible in the full population. Same-platform grouped validation and unseen-repository diagnostics do not demonstrate cross-hardware transfer.

## Completed bounded comparison and stopping rule

The companion [training experiment](d9/train-calibration-descriptor-experiment.json) compares original-class medians with static command-mechanism median backoff on 23245 `train_calibration` tool events using five fixed hash-by-instance folds. Its 545 observed instance clusters come from 546 eligible manifest clusters; the artifact's original `trajectory_count` field names the observed instance count. Repeated settings of an instance stay in one fold. The minimum support is fixed at 25 events and three instances. Measured durations are training targets, never current-event input features.

Within-25% coverage rises from 67.744% to 72.390%, and absolute-error mass falls 16.10%; mean APE rises from 37.35% to 38.20% and maximum APE from 481.08% to 4181.50%. All 6418 remaining misses remain in the denominator. This identifies a useful descriptor effect against the stated coarse baseline, not an improvement over frozen v3, a safe production replacement, a fresh holdout result, atomic-syscall accuracy, or hardware transfer. The experiment supplies no new universal D9 pass.

The mechanism diagnostic and this one comparison close the bounded model work. Further adaptive searches are not justified by the average gain. The already declared configuration comparison remains the score-selection route; no further sweep, prompt search, hardware trial, fresh holdout access or acquisition extension follows from this review.
