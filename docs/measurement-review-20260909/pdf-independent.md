## Cross-cutting reconstruction conditions

1. **Join chain:** suite/case → attempt/configuration → agent action → process/tree/cgroup + atomic CPU event; case/attempt → logical model call → retry → physical proxy request → independent serving observation → endpoint/server epoch/GPU. Worker/host identifiers alone do not make request IDs unique after restart; preserve attempt and producer epoch. Preserve accepted-versus-abandoned attempt decisions.
2. **Clock contract:** local monotonic intervals require boot/clock-domain identity. Cross-host native durations can be joined by request identity without subtracting unrelated clocks. A unified timeline requires measured mapping/uncertainty. Nesting/request intervals must not be blindly added to CPU syscalls or native-serving subintervals. Server wall and native prefill/decode are still not automatically GPU kernel execution time.
3. **Lifecycle accounting:** keep outer start/end, explicit named intervals, dependency/order and genuine unaccounted gaps. Complements can honestly describe unaccounted time; relabeling them “CPU overhead” cannot explain or model it. Setup/evaluator time should remain separately reconstructable because benchmark agent E2E and total infrastructure runtime are different quantities.
4. **Durable raw evidence:** accepted results must reference retrievable, verified complete CPU stream/decoder/schema, request bodies/responses/native observer stream, artifact/source/model/hardware manifests, patches and evaluator reports. Counts in summaries cannot repair missing raw records after a VM dies. Preserve corruption/loss/watermark/censor status.
5. **Prediction-time distinction:** Step 3→4 supports a trace-driven simulator conditioned on observed workload descriptors; the PDF does not demand guessing a future agent trajectory. Realized output tokens or CPU operation work can be legitimate **declared fixed-work replay inputs**. They cannot silently become prospective inputs for a before-execution claim. Current-event wall/CPU/CUDA timing is a target and cannot predict itself. A conditional replay result must not be advertised as unconditional new-case E2E prediction. Model/configuration and feature availability need to be explicit before final acceptance.

## Necessary versus nonblocking

**PDF-required:** outcome/E2E/suite/configuration identity, sample/category timing, four effective sweeps, selected individual CPU/GPU events, tokens/context/work, faithful breakdown, hardware-parameterized model inputs, strict event/E2E labels and reusable figure data.

**Scientific explanation/validity:** native serving versus transport distinction; actual CPU-host attribution, enough lifecycle/CPU/IO/cache/concurrency context to support the chosen causal/model claims; mutable workload state when required to reconstruct work; capture-loss and perturbation evidence. A demonstrated omission affecting these can delay acquisition.

**Debug only:** redundant status snapshots, verbose monitor logs, additional process inventories after equivalent durable identity is established, human-readable copies of fully decodable raw evidence. Useful for recovery; not automatically acquisition gates.

**Speculative:** blanket kernel tracing, every possible hardware counter, arbitrary multi-platform full reruns, bigger sweeps, new prompts/models, maximal telemetry unrelated to a specified model or observed explanatory gap. None is a PDF prerequisite.

This reading alone supports **no acquisition PASS yet**: raw-artifact reconstruction and current-stack source binding belong to the assigned reconstruction review. Nor does acquisition completeness prove eventual D9 accuracy. The finite stopping point is: the raw measurements and provenance needed above survive and reconstruct; any remaining event-model accuracy failure is honestly evaluated postcollection rather than concealed or used to launch open-ended telemetry work.
